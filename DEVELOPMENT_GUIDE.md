## Quick Start

### Prerequisites

- Docker Desktop running
- kubectl installed
- kind (`go install sigs.k8s.io/kind@latest`)
- (Optional) Tilt (`curl -fsSL https://raw.githubusercontent.com/tilt-dev/tilt/master/scripts/install.sh | bash`)

### Fast Path (Using Tilt)

```bash
# 1. Create Kind cluster with GPU nodes
cd cmd/provisioner
go run main.go  # Creates hpc-sentinel-dev cluster

# 2. Start Tilt (auto-rebuild on changes)
cd ../..
tilt up

# 3. Press SPACE to open Tilt UI
# 4. Edit code - Tilt automatically rebuilds and reloads!

# 5. Create test HPCJob
kubectl apply -f config/samples/hpc_v1alpha1_hpcjob.yaml

# 6. Watch it (won't work until controller is implemented!)
kubectl get hpcjobs -w
```

### Manual Path

```bash
# 1. Create Kind cluster
cd cmd/provisioner && go run main.go && cd ../..

# 2. Build and load images
./build/scripts/build-all.sh dev
./build/scripts/load-to-kind.sh hpc-sentinel-dev dev

# 3. Install CRDs
make install

# 4. Deploy operator
make deploy IMG=localhost:5001/kube-hpc-sentinel-manager:dev

# 5. Create HPCJob
kubectl apply -f config/samples/hpc_v1alpha1_hpcjob.yaml
```

## Development Roadmap

### Phase 1: Design Your API (CRDs)

**Goal**: Define what resources your operator manages.

For an HPC workflow operator managing GPU deployments, you likely need:

1. **HPCWorkflow** - Represents a complete workflow with all-or-nothing semantics
2. **GPUResourcePool** - Manages GPU node pools/clusters (optional, could use native k8s)
3. **WorkflowRun** - Represents an execution instance of a workflow (optional)

**Example HPCWorkflow structure**:
```yaml
apiVersion: nvidia.com/v1alpha1
kind: HPCWorkflow
metadata:
  name: training-pipeline
spec:
  # All-or-nothing deployment requirements
  requiredResources:
    gpus:
      count: 8
      type: "nvidia-a100"
      topology: "nvlink"  # GPUs must be interconnected
    memory: "512Gi"
    storage: "10Ti"

  # Workflow steps
  steps:
    - name: data-preprocessing
      image: myrepo/preprocess:v1
      resources:
        gpus: 2
    - name: model-training
      image: myrepo/train:v1
      resources:
        gpus: 4
    - name: evaluation
      image: myrepo/eval:v1
      resources:
        gpus: 2

  # All-or-nothing semantics
  deploymentPolicy:
    mode: "atomic"  # Deploy all or nothing
    timeout: "30m"
    rollbackOnFailure: true
```

### Phase 3: Implement Controller Logic

**File**: `internal/controller/hpcworkflow_controller.go`

**Key responsibilities**:

1. **Reconcile function** - Core logic loop
   ```go
   func (r *HPCWorkflowReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
       log := log.FromContext(ctx)

       // 1. Fetch the HPCWorkflow instance
       var workflow nvidiav1alpha1.HPCWorkflow
       if err := r.Get(ctx, req.NamespacedName, &workflow); err != nil {
           return ctrl.Result{}, client.IgnoreNotFound(err)
       }

       // 2. Check resource availability (all-or-nothing)
       available, err := r.checkResourceAvailability(ctx, &workflow)
       if err != nil {
           return ctrl.Result{}, err
       }

       if !available {
           // Resources not available - wait and requeue
           workflow.Status.Phase = "Pending"
           r.Status().Update(ctx, &workflow)
           return ctrl.Result{RequeueAfter: 30 * time.Second}, nil
       }

       // 3. Atomically allocate resources
       if err := r.allocateResources(ctx, &workflow); err != nil {
           return ctrl.Result{}, err
       }

       // 4. Deploy workflow steps
       if err := r.deploySteps(ctx, &workflow); err != nil {
           // Rollback on failure
           r.rollbackDeployment(ctx, &workflow)
           return ctrl.Result{}, err
       }

       // 5. Update status
       workflow.Status.Phase = "Running"
       return ctrl.Result{}, r.Status().Update(ctx, &workflow)
   }
   ```

2. **Resource checking** - GPU availability

### Phase 5: Configure Manager Deployment for GPUs

**File**: `config/manager/manager.yaml`

Your controller manager pod probably **doesn't need GPUs** (it just schedules workloads), but it should run on control plane nodes:

```yaml
spec:
  template:
    spec:
      # Run on control plane or non-GPU nodes
      affinity:
        nodeAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
          - weight: 100
            preference:
              matchExpressions:
              - key: node-role.kubernetes.io/control-plane
                operator: Exists

      # Tolerate control plane taints
      tolerations:
      - key: node-role.kubernetes.io/control-plane
        operator: Exists
        effect: NoSchedule
```

However, the **workflow Pods/Jobs** you create will need GPU specifications:

```yaml
# Example Job created by your controller
apiVersion: batch/v1
kind: Job
metadata:
  name: workflow-step-training
spec:
  template:
    spec:
      containers:
      - name: trainer
        image: myrepo/train:v1
        resources:
          limits:
            nvidia.com/gpu: "4"  # Request 4 GPUs

      # GPU node affinity
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: nvidia.com/gpu.product
                operator: In
                values:
                - "NVIDIA-A100-SXM4-40GB"

      # GPU node tolerations
      tolerations:
      - key: nvidia.com/gpu
        operator: Exists
        effect: NoSchedule
```

## Questions to Consider

Before diving into code, think about:

1. **What defines a "workflow"?**
   - Is it a DAG of steps?
   - Are steps Pods, Jobs, or custom resources?
   - How do steps communicate (shared storage, APIs)?

2. **What does "all-or-nothing" mean?**
   - All GPUs available before starting?
   - All steps deploy successfully or rollback?
   - How long to wait for resources?

3. **GPU topology requirements**
   - Do all GPUs need to be on one node?
   - Do you support multi-node GPU clusters?
   - What about NVLink/NVSwitch requirements?

4. **Failure handling**
   - Retry failed steps?
   - Partial rollback vs full rollback?
   - Dead letter queue for failed workflows?

5. **Resource lifecycle**
   - When to release GPUs?
   - Keep resources allocated between steps?
   - Support for long-running workflows?
